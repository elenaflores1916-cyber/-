# 心相引擎 · 独立判定（SillyTavern 扩展）

把原「心相引擎」世界书方案里**"靠主 API 在 `<thinking>` 里自掷骰、自算阈值、自复制快照"**的判定方式，改造为一个独立插件：

> 每回合由插件用**单独一次副 API 思考**完成推演，骰子由插件真随机掷出，阈值与区段由插件本地公式机械结算，性格存档由插件持久化，并**连接柏宝书记忆插件**读取剧情记忆。

## 它解决了旧方案的什么问题

| 旧方案（世界书 + 主API思考） | 本插件 |
|---|---|
| `{{roll:1d100}}` 宏不生效时 AI 自己编骰值；AI 可能改判迎合用户 | 插件用 `crypto` **真随机掷骰**，主/副API都只能"原样引用"，物理上无法编造或改判 |
| AI 自己算 `80−铺垫×10−…`，算错/虚报增益无法拦截 | 阈值与区段由**插件本地公式复核**，增益自动钳制（≤2项、单项≤10），副API算错直接被机械覆盖 |
| 快照靠"原样复制上一楼"，删楼/正则作用域错误就**断链**，整个系统白搭 | 存档（轴/档序/铺垫/心结/心锚）保存在**聊天元数据**里，跟随聊天走，永不复制断链 |
| 每楼 1000~1500 token 思考块占用主API，正文模型服从性要求高（Claude/Gemini 级） | 主API只收一段 300~500 token 的**已结算判定注入**，只负责写正文；小模型也能用 |
| 判定、推演、正文在同一次生成里互相污染 | 推演由**副API单独一次 quiet 调用**完成（不进聊天记录、不占主API、不打断正文风格） |

## 与柏宝书（ST-BaiBai-Book）的分工

- **剧情记忆归柏宝书**：摘要、总结、物品/NPC台账、向量检索照常工作。
- **人格存档归心相引擎**：性格轴/档序/铺垫/心结/心锚存于聊天元数据，换聊天自动隔离。
- **判定时合并读取**：插件通过柏宝书公开只读API（`globalThis.STBaiBaiBook.getSnapshot()` / `getHistory()`）拿到时间地点、主角状态、NPC台账与压缩历史，喂给副API做判定输入。
- **长期闭环**：判定结论落进正文后，柏宝书摘要会自动吸收"她上次绕了路""她这次站住了"这类事实；下一回合判定读历史时就能看到——这正是原方案"记忆是重构式的"的实现基础。
- **未安装柏宝书**：自动降级为读取最近 N 楼原文做判定上下文，功能可用但没有长期记忆与状态台账。

柏宝书公开API v1 为**只读**（无写入接口），所以心相存档由本插件独立维护，这是设计内的分工而非缺陷。

## 安装

**方式A · 本地手动安装（推荐，无需 git）**

把 `heart-engine` 整个文件夹复制到：

```
SillyTavern/public/scripts/extensions/third-party/heart-engine/
```

重启酒馆（或刷新页面），在「扩展 → 管理扩展」里看到"心相引擎 · 独立判定"并启用。

**方式B · 通过扩展安装器**

把本文件夹推到一个 git 仓库，然后「扩展 → Install extension」粘贴仓库地址。

## 配置（扩展面板）

| 项 | 说明 | 默认 |
|---|---|---|
| 启用 | 总开关 | 开 |
| 自动判定 | 每次生成前自动判定；关掉后用 `/heart` 手动 | 开 |
| 世界骰 | 与人无关的偶然（桥断不断/是否被发现） | 开 |
| 严格复核 | 副API返回JSON无效或区段算错时自动重试一次 | 开 |
| 基准阈值 | 阈值公式的基准值：90=慢热珍贵，80=默认（约20%会"做"），65=更快勇敢 | 80 |
| 上下文楼数 | 本地降级时读取的最近楼层原文数 | 3 |
| 判定角色上限 | 每楼全量判定的角色数（心相分析焦点制） | 2 |

副API说明：判定调用走酒馆的 quiet 生成，默认**跟随当前主API**；想换渠道，用酒馆自带的 Connection Manager 指定 quiet 连接即可（与柏宝书摘要的"副API渠道"思路一致）。

## 与旧世界书的关系（重要）

同时保留两套会打架。已导入 `心相引擎_世界书.json` 的话：

1. **禁用**世界书全部三条：「主法则」「回复格式」「尾部复读」——插件的副API提示词已内嵌法则精简版，主API的注入已内嵌铁律与尾部复读；
2. 预设里旧的 `<thinking>` CoT 模板**删掉或换回普通模板**——判定不再需要主API思考；预设中"保持创新、规避相似性"等正文风格段落可以照常保留（那属于正文层面，与判定无关）；
3. 不再需要折叠正则（主API根本不输出思考块）。

斜杠命令：`/heart` 手动判定一次（自动判定关闭时用）；`/heart-reset` 重置本聊天心相存档。

## 每回合流程

```
点生成
 → 插件读柏宝书快照/压缩历史 + 本地心相存档
 → 插件真随机掷 落子骰 + 世界骰
 → 副API单次思考（≤2个岔路口角色：岔路口定义、增益申报、推演素材）
 → 插件本地复核：增益钳制 → 阈值公式 → 区段归属（算错自动重试/覆盖）
 → 更新心相存档（档序+1 / 铺垫+1 / 心结 / 定音），随生成成功落账
 → 把「骰账+行为裁决+推演素材」注入主API上下文
 → 主API只写正文（不掷骰、不复算、不维护快照）
```

区段→裁决（与原版六区段一致）：1~5 应激崩溃｜6~阈−11 不做｜阈−10~阈−1 其它（第三条路）｜阈~阈+15 险胜｜阈+16~95 坚定（档序+1）｜96~100 本能。"其它"区段拿不出第三条路时按主法则机械降级为"不做"。

## 对账与监督

扩展面板实时显示：柏宝书连接状态、各角色档序/铺垫、最近 6 次判定记录（楼层号/骰值/阈值/区段）。每条账目格式：

```
爱丽丝｜勇气轴:动摇(档序2)｜铺垫:2
落子骰:47(系统真随机)｜增益:重要之人在身后+10｜算式:80−20−10−10＝40｜区段:险胜
```

三项核对：增益是否 ≤2 项单项 ≤10 且有现场依据；算式是否与存档一致；骰值是否真的落在声称的区段里。因为骰值与算式都是插件结算的，对账从"监督AI有没有作弊"变成了"确认插件工作正常"。

## 重 roll（swipe）行为

每次 swipe 都会**重新真掷骰、重新判定**——这正是原版"落子应散开"的验收目标，现在由真随机保证。落账绑定生成成功的楼层，swipe 中间态不污染存档。

## 验收清单（10 分钟）

1. 发一条消息 → 弹出"心相引擎·判定中（落子骰 X）"提示；
2. 生成完成后，扩展面板出现判定记录，心相存档出现新建角色档案；
3. 同一岔路口连续 swipe 十几次 → 面板记录里骰值散开、区段分布符合基准阈值预期（80 基准：约 2~3 次做、1~2 次其它、其余不做）；
4. 制造铺垫级小事 → 下一次判定时该角色"铺垫"数字 +1、阈值下降；
5. 关闭柏宝书总开关再生成 → 面板显示"未检测到"，判定仍工作（本地降级）。

## 限制与坑

- **副API质量决定推演质量**：骰值/阈值/区段是机械的，但"不做的力量/定音/记忆浮现"等推演文案仍取决于副API模型的水平，建议与主API同级或使用柏宝书同款副渠道。
- **生成前会多等一次副API调用**（约 5~20 秒）：正常现象，弹窗会显示骰值。超时（90s）自动放行为无判定。
- **生成中途刷新页面**会丢失该楼落账（存档少更新一次），下一回合判定会自动基于当前存档继续，无需干预。
- **swipe 失败**（生成报错）极端情况下可能把该楼账目提前落账一次，误差一回合，可 `/heart-reset` 或手动忽略。
- 插件在酒馆静默生成（type=quiet，如柏宝书摘要）与 impersonate 时不触发，无递归风险。
- 柏宝书 `coverage.complete=false`（有缺摘要楼层）时快照可能有缺口，插件照常使用，README 层面不阻塞。
